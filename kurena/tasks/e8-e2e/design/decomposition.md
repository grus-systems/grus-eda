# e8-e2e — Reference-power decomposition

The acceptance allows a gcd miss only when it is decomposed into a
power-estimator axis and a mesh/solver axis. This ticket makes the
required OpenSTA per-instance feed reproducible and always available
to the Rust test, then uses the same decomposition for picorv32's
named floor.

## Publishing `inst_power.tcl`

`generate_irdrop_ref.sh` already emits
`tests/designs/<d>/runs/irdrop/inst_power.tcl` in step B:

```tcl
set_pdnsim_inst_power -inst {<instance>} -power <total_watts>
```

That directory is gitignored. Update step D to copy the file to:

```text
tests/designs/<d>/<d>.irdrop.inst_power.tcl
```

and extend `<d>.irdrop.reference.json`'s existing `inst_power_feed`
object with:

```json
"feed_file": "<d>.irdrop.inst_power.tcl",
"feed_size_bytes": 12345,
"feed_sha256_16": "0123456789abcdef"
```

The existing `applied`, `report_rows`, `inst_count`, and
`inst_feed_total_w` fields remain the coverage and total checks. The
feed is a generated golden input like the voltage CSVs, not a
hand-written table. Rerun the committed script on both designs and
`git diff` all generated outputs; the rerun count goes in
`docs/results.md`.

Both committed feeds are under the 1 MB rule: 384 lines for gcd and
10,205 lines for picorv32.

## Provenance caveat

`set_pdnsim_inst_power` is additive in the pinned image, so this file
is not a mechanism that reproduces PDNSim's embedded convention. It is
still the correct decomposition input required by the acceptance: it
is the per-instance `report_power` feed regenerated by the committed
script, and `inst_feed_total_w` is the measured sum actually supplied
to the annotation surface.

Record both totals in the results entry:

- `embedded.total_power_w` — the rounded total printed by
  `analyze_power_grid`;
- `inst_power_feed.inst_feed_total_w` — the full-precision feed sum.

Any residual on the reference-feed axis is therefore named
"mesh/solver + embedded-feed provenance", not simply "solver", unless
the two totals coincide within the comparison precision.

## Axes

For each design and net, three maps produce two differences:

```text
ours_n7       = solve(mesh, N7 per-instance power)
ours_refpwr   = solve(mesh, OpenSTA inst_power.tcl per-instance power)
reference     = embedded golden CSV

estimator_axis = |V(ours_refpwr) − V(ours_n7)|
mesh_axis      = |V(reference)  − V(ours_refpwr)|
total_axis     = |V(reference)  − V(ours_n7)|
```

The solves share `PdnMesh`, source clamps, `current_scale_v`, and
sink splitting, so the estimator axis is exactly the voltage effect of
substituting per-instance powers. The mesh axis is the remaining
geometry/model/solver/provenance residual.

For each axis print the same `MapStats` as the gate plus scalar
worst/avg deviation deltas. For the estimator axis, also print the
per-instance power-feed totals:

```text
sum(N7 total_w), sum(inst_power.tcl total_w), delta
```

## Reading the axes

- `estimator_axis` outside the per-pin bound and `mesh_axis` inside →
  named residual: **power estimator**.
- `mesh_axis` outside and `estimator_axis` inside → named residual:
  **mesh/solver** (plus the provenance caveat above if the feed and
  embedded totals differ materially).
- both outside → report both residuals; do not collapse them into a
  generic "model" cause.
- a total miss with both axes inside → a new interaction or rounding
  artifact; investigate before changing bounds.

## Expected use in the tests

`test_irdrop_reference_power_axis` runs the feed solves on both
designs unconditionally once the committed feed exists. It is a
diagnostic test: it asserts the feed's coverage/total and each map's
row set, prints the three axes and top-5 deviations, and does not
invent a new tolerance before the axis has been measured.

If the gcd gate misses, the implementation copies these printed axis
numbers into `docs/results.md`, names the residual, and only then
considers a bounded constant. If picorv32's VGND floor is needed, the
same table names whether the floor is dominated by the N7 feed, the
mesh model, or the embedded-feed provenance difference.

# e8-e2e — Documentation and version contract

The implementation commit must update the verification record and the
current-status pages in the same change. The E8 stage should not be
called fully clean unless the fresh measurements actually pass.

## `docs/results.md`

Add one dated entry (target date 2026-11-23 or the actual run date):

```text
### <date> — e8-e2e: IR-drop end-to-end gate vs PDNSim embedded goldens
```

Required content:

- commands verbatim: test command, clippy/test commands, and the two
  `generate_irdrop_ref.sh` reruns used to publish `inst_power.tcl`;
- artifact table for the new feed files with size and SHA-256 prefix;
- per design/net gate table:
  - rows and row-set verdict;
  - max/median/P99 `|ΔV|` and strict-tolerance row count;
  - scalar avg and worst drop/bounce, ours/reference/delta/tolerance;
  - total-power delta;
- top-5 deviation pins per net with instance, terminal, coordinates,
  ours V, reference V, signed `ΔV`, and bound;
- sign convention sentence: `Voltage` is absolute node potential on
  both nets; `VPWR` deviation is a positive drop below `1.8 V`,
  `VGND` deviation is a positive bounce above `0 V`;
- decomposition table: estimator axis, mesh axis, total axis, feed
  totals, and the named residual;
- fail-proof mutation and restore;
- what was actually run vs. reused, including the container image and
  whether committed ours CSVs were regenerated or only compared.

Keep the earlier `e8-solve` entry intact. Do not rewrite its numbers;
this entry supersedes them with the stricter per-pin verdict.

## `docs/status.md`

Update the E8 row to the measured verdict. On the committed starting
point the correct language is approximately:

- gcd: `PASS` — both nets meet the worst-drop and per-pin bounds;
- picorv32: measured and bounded — worst-drop/bounce meets
  `max(5%, 5 mV)`, VPWR meets the per-pin bound, VGND has a named
  residual bounded by the measured floor.

If the reference-power axis proves the residual is estimator-only,
say so. If it is mesh/solver or provenance, say that instead. Remove
the current overclaim that every per-pin delta is inside the roadmap
tolerance.

Update the E8 section:

## `tests/designs/README.md`

Extend the IR-drop variants paragraph/table with

## Version

Planned implementation has no public Rust API and no CLI flag:

- `crates/grus-core/tests/irdrop.rs` is test-only;
- script/artifact/docs changes are verification data;
- workspace `version` therefore stays `0.7.4`, and `Cargo.lock` does
  not change.

If implementation introduces a public comparator API or CLI option,
revisit this decision in the same commit and bump `0.7.4 → 0.7.5`
under the repository's 0.x patch rule.

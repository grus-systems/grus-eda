# e6-drt-e2e: reference gate — Magic/OpenROAD on our routed DEF

E6 ticket 7 (stage gate), depends on `e6-drt-emit`. Runs the real
deck on OUR routed DEF in the pinned container — the same gate
every stage carries — and compares against the committed
`e6-drt-ref` surfaces.

## Scope

1. **Reference script** — extend `tests/designs/generate_drt_ref.sh`
   (or a sibling `check_ours_drt.sh`) to run Magic `drc(full)` +
   OpenROAD `detailed_route` report on `<d>.ours.routed.def` inside
   `ghcr.io/librelane/librelane:3.0.16` — the identical checks the
   baseline/delegated variants carry in `<d>.drt.reference.json`.
   Output: `<d>.drt.ours.reference.json` committed (small).
2. **Gate test** — `<d>.drt.ours.routed.def` (generated by the
   committed `generate_drt_ours.sh` path) is scored: Magic
   `drc listall why` per-rule counts on our DEF must be 0 for every
   `lef_expressible` rule (the subset Magic's clean reference also
   shows 0 on), and `magic_total` deltas are decomposed — any
   magic_only finding on our DEF is named per rule (master-internal
   classes are design-inherited and identical to the placed DEF's,
   not routing-caused — that distinction is the point of the
   decomposition).
3. **Comparison table** — wirelength, via census, antenna report vs
   the `baseline`/`delegated` variants — informational, with named
   deltas (same honest-delta convention as E8).
4. **Determinism** — `generate_drt_ours.sh` run twice emits
   byte-identical DEF.

## Revision note 2 (2026-11-24, external review — mechanism for the residual spacing class)

An outside review of the merged drt module (post-`4c7831b` dev)
named the exact mechanism that lets a wire land on a foreign pin
with no router-side record — evaluate it while designing the
met1.2/met2.2 residual fix:

- `Pin` marks are soft-priced even in `hard` mode —
  `maze.rs` `hit_verdict` doc: "own free, foreign soft-priced —
  never a hard block". A wire may cross a foreign pin shape at any
  iteration, and the final hard pass does not forbid it.
- `Occupant::Pin` hits are excluded from `Collision` records
  (`maze.rs` collision collection keeps only `Occupant::Net`), so a
  pin-overlapping wire never triggers rip-up of the offending net.
- `project_attach` paints an axis-aligned stub from the attach node
  to the pin rect (`maze.rs` "Projected-pin access stubs") — a stub
  clipped to *own* raw pin rect still stops nothing w.r.t. a
  foreign pin a half-spacing away.

Interpretation aid for the golden: `li.3`/`li.c2` reporting equal
counts likely double-counts one violation pair under two rules —
compare bboxes before treating the numbers as independent.

If the residual fix lands this mechanism (foreign-pin footprint
made a hard block or a recorded collision → wire-side rip-up),
note it in `docs/results.md`; if it remains open, it becomes its
own ticket (`kurena/tasks/drt-pin-collision`).

# e4-sta-e2e — Reference and artifact generation

Two generators, run in order:

1. `tests/designs/generate_guide_ours_spef.sh <design>` — **host side**, our
   binary; emits the artifacts under test.
2. `tests/designs/<d>/generate_ref.sh` step 9c — **pinned image**,
   OpenROAD/OpenSTA; emits the endpoint reference JSON.

Step 9c consumes outputs of step 1, so the run order is 1 then 2 on each
design. Both generators are committed; every golden they emit is
regenerable and verified byte-identical on rerun (`git diff` empty, E0
lesson 1).

## 1. `tests/designs/generate_guide_ours_spef.sh`

New committed top-level script (mirrors `generate_prop_ref.sh`'s shape —
design name as `$1`, `${PDK_ROOT:-$HOME/.ciel}` PDK lookup, loud failure
on missing inputs). Emits two artifacts per design via the literal
criterion-4 chain:

```sh
cargo build --release -p grus-eda
GRUS=target/release/grus-eda
$GRUS route \
    --tlef "$PDK_TLEF" --lef "$PDK_LEF" \
    --def "tests/designs/$D/$D.placed.def" \
    --guide-out "tests/designs/$D/runs/guide-check/$D.ours.guide"
$GRUS sta \
    --lib "$PDK_LIB" --tlef "$PDK_TLEF" --lef "$PDK_LEF" \
    --def "tests/designs/$D/$D.placed.def" --sdc "tests/designs/$D/$D.sdc" \
    --parasitics guide --guide "tests/designs/$D/runs/guide-check/$D.ours.guide" \
    --spef-out "tests/designs/$D/$D.guide.ours.spef"
```

- `runs/guide-check/<d>.ours.guide` — the intermediate, gitignored under
  the existing `tests/designs/<d>/runs` rule; the same path
  `check_guide_readback.sh` defaults to (the e4-1/e4-2 convention), so the
  read-back script keeps working on it unchanged. `sta --parasitics guide
  --guide` parses it back through `parse_guides`/`resolve_guide_nets`,
  exercising the file handoff the criterion names — equivalent to the
  no-`--guide` internal route (`route_design` + `build_guides` feeds the
  same builder); record the equivalence, do not generate a second SPEF.
- `<d>.guide.ours.spef` — `write_spef` output. `gcd.guide.ours.spef`
  commits (OpenROAD's own `gcd.guide.spef` is ~200 KB; ours lands in the
  same order — verify size at generation and if it exceeds 1 MB gitignore
  it instead, same rule). `picorv32.guide.ours.spef` is gitignored (~5 MB
  like `picorv32.guide.spef`).
- `write_spef` emits a fixed `*DATE "00:00:00 Thu 01 01, 1970"` and is
  deterministic (`test_guide_emit_deterministic` /
  `test_guide_parasitics_deterministic` cover both inputs), so a rerun of
  this script must produce a byte-identical file — `git diff` empty on the
  committed copy is part of the record.
- picorv32 additionally needs `picorv32.placed.def` (gitignored,
  regenerated by `generate_ref.sh`) — fail loudly if absent; the kurena
  worktree seed covers it.

## 2. `generate_ref.sh` step 9c (both designs)

Appended after step 9b, sourcing the same `collect_endpoints.tcl` proc
(`find_timing_paths -endpoint_path_count 1 -group_path_count 1000`, the
8-field `endpoints` array). Three `openroad -no_init -no_splash`
invocations — one per block — so each `read_spef`/`estimate_parasitics`
starts from a clean parasitics state (the step-9b precedent; parasitics
are not re-read over each other in one process). Header comments of both
scripts gain `<d>.guide.sta.reference.json`.

Block 1 — the gate reference, `guide_spef` (write mode):

```tcl
source /work/tests/designs/<d>/runs/canonical/collect_endpoints.tcl
read_liberty ...tt_025C_1v80.lib
read_lef ...sky130_fd_sc_hd__nom.tlef
read_lef ...sky130_fd_sc_hd.lef
read_def /work/tests/designs/<d>/<d>.placed.def
read_sdc /work/tests/designs/<d>/<d>.sdc
read_spef /work/tests/designs/<d>/<d>.guide.spef
# wns/tns via sta::worst_slack/-min, sta::total_negative_slack (already
# user units); endpoints via collect_endpoints_json
set fp [open "/work/tests/designs/<d>/<d>.guide.sta.reference.json" "w"]
puts $fp "{" ... "  \"guide_spef\": {" ...   # same layout as a sta.reference.json mode
close $fp
```

`read_spef` on the committed `<d>.guide.spef` is the literal
"read_guides-driven `-global_routing` SPEF" the criterion names — step 5d
proved `read_guides` read-back reproduces the in-memory guide parasitics
per-net exactly, so this reads the committed artifact itself (E0 lesson
2).

Block 2 — `guide_ours_spef` (append):

```tcl
# same preamble; then
read_spef /work/tests/designs/<d>/<d>.guide.ours.spef
# -> appends "guide_ours_spef" block to <d>.guide.sta.reference.json
```

OpenSTA `read_spef` on our `write_spef` output. This is also the SPEF
interop check: `write_spef`'s header and `*CONN` naming deliberately
mirror OpenROAD's (`parasitics.rs` comment); if OpenSTA rejects our file
that is a finding — fix `write_spef`, do not drop the block silently.

Block 3 — `guide_ours_readback` (append + closing `}`):

```tcl
# same preamble; then
set_wire_rc -layer met2
read_guides /work/tests/designs/<d>/runs/guide-check/<d>.ours.guide
estimate_parasitics -global_routing
# -> appends "guide_ours_readback" block and closes the JSON
```

In-memory guide parasitics on our guide file (no intermediate SPEF —
`find_timing_paths` consumes `estimate_parasitics` directly, like the
`placement_rc` mode). `set_wire_rc` first, per step 5d (`EST-0018`).
`EST-0026` "Missing route to pin" warnings are expected on our guides
(e4-2 counted gcd 11 / picorv32 249 on the read-back path): warnings are
not failures — count them from the run log for the results entry.

Guard (in the script, before the Tcl): step 9c errors out unless
`<d>.guide.ours.spef` and `runs/guide-check/<d>.ours.guide` exist, naming
`tests/designs/generate_guide_ours_spef.sh` as the producer — no silent
empty blocks.

## Golden JSON schema

Identical block layout to a `<d>.sta.reference.json` mode so
`compare_design_files` consumes it untouched:

```json
{
  "design": "gcd",
  "guide_spef": {
    "wns_max_ns": ..., "tns_max_ns": ..., "wns_min_ns": ..., "tns_min_ns": ...,
    "endpoints": [ {"pin": "...", "max_arr_ns": ..., "max_req_ns": ...,
      "max_slack_ns": ..., "max_slew_ns": ..., "min_arr_ns": ...,
      "min_req_ns": ..., "min_slack_ns": ..., "min_slew_ns": ...}, ... ]
  },
  "guide_ours_spef": { ... },
  "guide_ours_readback": { ... }
}
```

- `gcd.guide.sta.reference.json` (3 blocks × 53 endpoints, ~50 KB) —
  committed.
- `picorv32.guide.sta.reference.json` (3 × 1,798) — gitignored with the
  rest of picorv32's generated artifacts; regenerated by the same step.

## `tests/designs/README.md`

Add to each design's artifact list (provenance, same shape as the
`gcd.guide.caps.txt` rows):

- `<d>.guide.ours.spef` — our `route --guide-out` guide →
  `estimate_guide_parasitics` → `write_spef`; produced by
  `generate_guide_ours_spef.sh`. gcd's is committed; picorv32's is
  gitignored and regenerated.
- `<d>.guide.sta.reference.json` — OpenSTA per-endpoint reference on
  three guide-parasitics modes (`guide_spef` gate reference,
  `guide_ours_spef`, `guide_ours_readback`), emitted by `generate_ref.sh`
  step 9c in the pinned image.
- `generate_guide_ours_spef.sh` (top level) — host-side generator of the
  `<d>.guide.ours.spef` artifacts; run it before `generate_ref.sh` step
  9c, which fails loudly without them.

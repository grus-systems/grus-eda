# e5-cts-e2e — Overview

E5 ticket 4 (final): score our CTS DEF against the committed TritonCTS
references per the scoping done-when
(`kurena/tasks/next-stage-scoping/design/done-when.md` §E5). This is a
**measurement ticket**: the constructor (`e5-cts-tree`, `v0.5.0`), the
mutation API (`e5-insert-api`), and the reference artifacts
(`e5-cts-ref`) already exist. Nothing in the tree constructor changes —
a failure here is recorded, decomposed, and bounded with a named cause,
not tuned away (AGENTS.md §2, §7.5).

## The four criteria and where each is measured

| # | Criterion | Ours | Reference | Bound |
|---|---|---|---|---|
| 1 | Skew | `max−min` of propagated `arrival_max[RISE]` at the register clock pins, our STA on our emitted CTS DEF | `latency_max_ns − latency_min_ns` in `<d>.cts.reference.json` (same surface: `arrival_max_rise` at `all_registers` `is_clock` pins) | `|ours − ref| <= max(25 ps, 25%·ref)` |
| 2 | Max insertion delay | `max` of the same per-pin set | `latency_max_ns` | `|ours − ref| <= 15%·ref` |
| 3 | E2e STA | per-endpoint arrival/req/slack, propagated `<d>.cts.sdc` STA on our CTS DEF | `cts_placement_rc` block of `<d>.cts.sta.reference.json` (OpenSTA propagated on the TritonCTS DEF) | `max(5 ps, 1%)` per field on gcd; picorv32 on its recorded floors (arr 6 ps, slack 40 ps, slew 10%, TNS 2.5%) |
| 4 | Honesty gate | `CtsReport` census + `clock_net_wirelength_um` | `inserted_instances`/`tree_buffers`/`dummy_loads`/`clock_net_wirelength_um` | informational — printed in the test, tabulated in `docs/results.md` |

Expected outcome, honestly stated up front (measured in the e5-cts-tree
entry of `docs/results.md`):

- gcd: skew 2.2 ps vs ref 1.37 ps spread → **inside** the 25 ps floor;
  insertion 0.306 vs 0.3145 ns → **inside** 15%. The e2e bound is the
  open question: our clock-pin latencies sit ~8 ps below the
  reference's, and arrival diffs of that order can pass 1% on ~3 ns
  endpoints while tripping the 5 ps absolute arm on small values.
- picorv32: skew 70.6 ps vs ref 36.2 ps spread → **outside**
  `max(25 ps, 9 ps)`; insertion 0.802 vs 0.7935 ns → inside 15%. The
  skew gap is the ticket's real investigation; `decomposition.md` is
  built to attribute it.

## Key decisions

- **Tests live in `cts::tests` (`cts/mod.rs`), self-contained.** The
  goal's Files scope is `crates/grus-core/src/cts/`. The comparison
  needs only what is already `pub(crate)`/public: `run_sta_with_state`
  (raised for ticket 3, `docs/e5-cts.md` §2.7) returning
  `StaReport.endpoints` — `EndpointReport.max_*`/`min_*` already carry
  the worst-slack polarity's tuple, the same values
  `analysis::tests`'s `pick_worst_polarity` default produces. The
  `resolve_tied_polarity` refinement is *not* reproduced; the
  escalation path is documented in `harness.md` and `tests.md`.
- **The DEF under test is the emitted text, re-parsed** — the same
  path T3/T5 already run (`write_def_full` → temp file → `parse_def`).
  The reference's own golden was collected on `<d>.cts.def` read back
  from disk (step C of `generate_cts_ref.sh`); ours is compared at the
  same boundary. The committed `gcd.cts.ours.def` is byte-proven equal
  to a fresh emission by the determinism test.
- **Skew surface is the per-pin spread, not `worst_clock_skew`'s
  signed pair.** The reference JSON's `skew_*_ns` is the signed
  worst-pair value (−34.16 ps on picorv32) while its `latency_*` fields
  are the per-pin extremes (36.2 ps spread) — a ~2 ps measurement-
  convention gap, which is exactly the "reference-setup" axis of the
  decomposition. Comparing spread-to-spread is apples-to-apples.
- **picorv32's engine axis needs `picorv32.cts.def`** — gitignored,
  absent in fresh checkouts, regenerated by the committed
  `generate_cts_ref.sh picorv32`. Its presence in CI requires the one
  ci.yml edit in `artifacts.md`. No silent skips: the decomposition
  test `require`s it loudly.
- **Named-residual pattern for anything outside bound** — the
  `Tol::PICORV32_GUIDE` precedent: measure, decompose, name the cause
  in `docs/results.md` and in the tolerance constant's doc comment,
  then hold the measured value. Never loosen without the named cause.
- **Version `0.5.0 → 0.5.1` (patch)**: additive tests, artifacts and
  docs; no production-API change. Recorded here per the goal's
  "record the choice".

# e6-drt-e2e-picorv32 — card #44: `unrouted_kinds` null-vs-fail (r1)

> **r2 status: landed** (`8496158`, v0.12.9) — the `fail` arm
> shipped and was exercised on a doctored log. Kept as record;
> remaining scope in `overview.md`/`recount.md`/`docs.md`/`steps.md`.

Medium-severity review item carried in `e6-drt-e2e`: the step-E
assembly's `unrouted_kinds` fallback violates its own documented
contract. This ticket fixes it while running the picorv32 leg —
the fix must land **before** the golden commit so the committed
`picorv32.drt.ours.reference.json` is "generated by the committed
script" including the fix.

## The contract (already documented, currently unenforced)

`kurena/tasks/e6-drt-e2e/design/scripts.md`:

> `unrouted_kinds` / `unrouted_blockers` objects (non-empty
> `unrouted` without kinds is `fail`, not `null`)

`kurena/tasks/e6-drt-e2e/design/golden.md`:

> `unrouted_kinds` — decomposition by `FailKind`; `null` only if
> the emit binary predates the line (the emit and script are
> version-locked; a present census line with a missing kinds line
> is a `fail`, not a guess).

## Current code (the bug)

`tests/designs/check_drt_ours.sh` step E, inside
`if ours_router["emit_log_present"]:`:

```python
mk = re.search(
    r"^unrouted_kinds NoPath=(\d+) Unattachable=(\d+)$", elog, re.M)
ours_router["unrouted_kinds"] = (
    {"NoPath": int(mk.group(1)), "Unattachable": int(mk.group(2))}
    if mk else None)
```

`mk is None` writes `null` unconditionally. But the emit binary
prints `unrouted_kinds` **unconditionally**
(`crates/grus-eda/src/main.rs`:
`println!("unrouted_kinds NoPath={nopath} Unattachable={unatt}")`
— no `unrouted`-emptiness guard), and the `guided=` census parse
three lines above already `fail`s when its anchored regex misses
(the `notch_fills=`/`notch_residuals=`/`hole_residuals=` version
lock). A log that parses `guided=` but lacks `unrouted_kinds` is
an emit/script version skew — the designed `fail` case — and
today it silently commits a `null` that the gate's `j_obj` then
panics on one indirection later, at test time instead of
generation time.

## The fix

Inside the same `emit_log_present` branch, after the `guided=`
parse has succeeded:

```python
mk = re.search(
    r"^unrouted_kinds NoPath=(\d+) Unattachable=(\d+)$", elog, re.M)
if mk is None:
    fail("emit log present but its unrouted_kinds line is missing "
         "or malformed (emit/script version lock)")
ours_router["unrouted_kinds"] = {
    "NoPath": int(mk.group(1)), "Unattachable": int(mk.group(2))}
```

Deliberately strict on both arms: `unrouted=0` with no kinds line
also fails — the emit prints the line unconditionally, so its
absence means version skew regardless of the census value. This
subsumes the scripts.md "non-empty `unrouted` without kinds"
wording.

## What stays

- `unrouted_blockers` keeps `if mb else None` — the emit prints
  the line **only when blockers were attributable**
  (`if !blk.is_empty()` in `main.rs`), so `null` is the
  contract-correct "none attributable" surface per golden.md
  ("`null` when no blockers were attributable. Recorded, not
  gated"). Do not flip it to `fail`.
- `emit_log_present == false` keeps writing the all-null
  `ours_router` block with `emit_log_present: false` — that is a
  recorded surface, and the gate's `j_obj`/`j_u64` accessors fail
  loudly on the nulls. Tightening the missing-log case to a
  step-E `fail` is out of the card's scope; note it here so a
  future ticket doesn't re-derive the distinction (missing
  *line* inside a present log = version lock, `fail`; missing
  *log* = recorded `emit_log_present: false`, gate-visible).
- No other parsing change — keep-list, allowlist, mutation block,
  Magic invocations untouched.

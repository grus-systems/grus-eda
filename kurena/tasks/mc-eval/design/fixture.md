# mc-eval — Fixture & reference regeneration

The committed `sta_clocks` fixture becomes a regression target this
ticket. Two gaps force fixture additions (AGENTS.md §7 rule 4: claim
coverage only for what an input exercises):

- The only `set_multicycle_path`/`set_max_delay`/`set_min_delay` lines
  in the existing scenarios cover **cross-domain** endpoints, which
  defer before the per-domain anchor code runs. Same-domain variants
  are needed to measure the capture-row arithmetic.
- No committed fixture puts a **latch** on a second domain, so the
  borrow-window per-domain read (api.md §6) has nothing discriminating
  to run against.

All reference numbers are regenerated by `probe.sh` in
`ghcr.io/librelane/librelane:3.0.16` — never derived by formula.

| `u_fa1/D` | `cka` | `cka` | evaluated |

| `ya` | `cka` | `cka` anchor | evaluated |
| `yb` | `ckb` | `ckb` anchor | evaluated |

Same-domain set: `u_fa0/D`, `u_fa1/D`, `u_fb1/D`, `ya`, `yb`.

`d_in` is anchored to `cka` in every file, so `u_fb0/D` is the
external-launch-into-domain-B deferral — keep it that way.

## 2. New scenarios on `two_clock.def`

Two files appended to `probe.sh`'s `SCENARIOS` (keep `t2_int` preamble
convention: `create_clock` pair + I/O delays + transition + loads):

**`t2_mcps.sdc`** — same-domain MCP, capture on `ckb`:

```tcl
# t2_int preamble (Pa=2.0, Pb=1.0) plus:
set_multicycle_path -setup 2 -from [get_cells u_fb0] -to [get_cells u_fb1]
```

Discriminates §1.6's capture-side rule: `u_fb1/D` req shifts by
`(2 − 1) * Pb`. If eval wrongly read `cka`'s 2.0 the shift is 2.0; the
golden pins the measured value. (`u_fb1/D` is the only covered endpoint —
the probe run measures the rest unchanged.)

**`t2_mds.sdc`** — same-domain delay checks on `ckb` with distinct
per-domain latencies/uncertainties:

```tcl
# t2_frac-style preamble (Pa=2.0, Pb=1.4) plus:
set_clock_latency 0.6 [get_clocks cka]
set_clock_latency 0.2 [get_clocks ckb]
set_clock_uncertainty -setup 0.05 [get_clocks cka]
set_clock_uncertainty -setup 0.15 [get_clocks ckb]
set_clock_uncertainty -hold 0.10 [get_clocks cka]
set_clock_uncertainty -hold 0.12 [get_clocks ckb]
set_max_delay 1.0 -from [get_cells u_fb0] -to [get_cells u_fb1]
set_min_delay 0.5 -from [get_cells u_fb0] -to [get_cells u_fb1]
```

`u_fb1/D`'s req anchors at `capture(ckb) + N`: `1.0 + 0.2 − 0.15 −
t_setup` max-side — the 0.6-vs-0.2 and 0.05-vs-0.15 asymmetries
discriminate a wrong-row read at 1 ps. Exercises `run_sta_partitioned`'s
delay-check anchor path end-to-end on domain B.

Exact line wording may be adjusted if OpenSTA rejects a form (record
the rejection — a finding, per the probe design).

## 3. `two_clock_latch.def` — second-domain latch

New minimal fixture (the borrow window needs a latch whose enable lives
on `cb`). Four cells, five pins, same conventions as `two_clock.def`:

```
COMPONENTS
- u_clka clkbuf_2  (clk1 -> net ca)
- u_clkb clkbuf_2  (clk2 -> net cb)
- u_ln   dlxtn_1   (GATE_N <- cb, D <- pin d2, Q -> net qln)
- u_fb0  dfxtp_1   (CLK <- cb, D <- qln)
- u_fa0  dfxtp_1   (CLK <- ca, D <- pin d1, Q -> pin ya)
NETS: clk1, ca, clk2, cb, d2 (pin -> u_ln/D), d1 (pin -> u_fa0/D),
      qln (u_ln/Q -> u_fb0/D), ya (u_fa0/Q -> pin ya)
```

`dlxtn_1` opens on the falling enable edge (existing `dlxtn` handling:
`open_pol = FALL`). With `Pb = 1.0`: open at `lat + 0.5`, close at
`lat + 1.0`.

**`t2_latch.sdc`**:

```tcl
create_clock -name cka -period 2.0 [get_ports clk1]
create_clock -name ckb -period 1.0 [get_ports clk2]
set_clock_latency 0.6 [get_clocks cka]
set_clock_latency 0.2 [get_clocks ckb]
set_clock_uncertainty -setup 0.05 [get_clocks cka]
set_clock_uncertainty -setup 0.15 [get_clocks ckb]
set_input_delay -max 0.7 -clock ckb [get_ports d2]
set_input_delay -min 0.1 -clock ckb [get_ports d2]
set_input_delay -max 0.5 -clock cka [get_ports d1]
set_input_delay -min 0.1 -clock cka [get_ports d1]
set_output_delay -max 0.5 -clock cka [get_ports ya]
set_output_delay -min 0.1 -clock cka [get_ports ya]
set_input_transition 0.1 [all_inputs]
set_load 0.05 [all_outputs]
```

`d2`'s max arrival lands inside the `ckb` transparent window → the
borrow clamp at `u_ln`'s output reads `close − unc − setup` with `ckb`'s
`period` (the `close <= open → close += period` wrap) and `ckb`'s
setup uncertainty. A domain-0 read would use `Pa = 2.0` — discriminating.
Every endpoint is same-domain (no cross paths in this DEF): `u_ln/D`
(closing check, `ckb`), `u_fb0/D` (borrowed launch, `ckb`), `u_fa0/D`
(`cka`), `ya` (`cka` anchor) — so the **full** endpoint table plus
wns/tns/violations compares cleanly against OpenSTA, and
`cross_domain_endpoints == 0`.

## 4. `probe.sh` changes

The script currently hardcodes `two_clock.def` and one `SCENARIOS` list.
Minimal generalization — keep the existing structure verbatim:

- `SCENARIOS` gains `t2_mcps t2_mds` → regenerated
  `two_clock.probe.json` plus `probe_t2_mcps.txt`, `probe_t2_mds.txt`.
- A second block runs `t2_latch` against `two_clock_latch.def` →
  `two_clock_latch.probe.json` + `probe_t2_latch.txt` (same
  `collect_endpoints_json`/`count_violations` procs, second
  consolidation output).

Re-run discipline (AGENTS.md §7 rules 1/9): run the whole script as
committed, `git diff` the artifacts — the 12 existing scenario blocks in
`two_clock.probe.json` and the existing `probe_*.txt` must be
byte-identical; only additive entries may appear. Say exactly what ran
in `docs/results.md`.

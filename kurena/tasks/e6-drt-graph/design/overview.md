# e6-drt-graph — Overview

E6 ticket 3: turn the committed per-net route guides (`<d>.guide`,
OpenROAD `global_route` output — ticket 1's reference files, not our
emission) into the guide-bounded on-grid graph the maze search will
walk. Depends on `e6-drt-tracks` (`drt::tracks` merged LEF∪DEF grid,
`drt::access` candidate access points) and on `congestion::guide`'s
parser/resolver, both landed.

## Ground truth discovered while planning

- **The join already exists.** `congestion::guide::parse_guides`
  parses the committed `tests/designs/<d>/<d>.guide` and
  `resolve_guide_nets` maps each block name to a `NetId` through
  `guide_net_name` (raw `net_def_spellings` when present), erroring
  on any guide name with no matching net — that is the spec's "extra
  net" case, already an error, never a skip.
- **Verified join on gcd**: all 269 guide blocks resolve to DEF nets.
  The only `net_names` nets absent from the guide are `VGND` and
  `VPWR` — `+ USE GROUND`/`+ USE POWER` records that live in the
  `NETS` section (`net_names` carries every NETS record; there is no
  net-level `+ USE` flag in `DesignDb`). Signal-ness must be derived
  from member pins (see `guide-join.md`).
- **Region scale measured** (independent Python model of the spec
  semantics on `gcd.placed.def` + `gcd.guide`): ~756k track-index
  pairs ("nodes"), ~1.45M induced-subgraph edges, **0**
  zero-coverage (net,layer) pairs. picorv32 is ~6× — still fine for
  tests. Work is O(Σ box ∩ tracks), not O(die).
- **The spec's literal AP check is degenerate — measured.** `access::
  rect_points` emits `(track, rect_midline)` points: an access
  point's own `(x,y)` is a track crossing only when the pin rect's
  midline happens to be a track coordinate. Measured on gcd: only 99
  of 933 member pins own such an AP — the literal
  `x ∈ tracks_x ∧ y ∈ tracks_y` rule would escape ~89% of pins,
  contradicting the spec's own expectation ("nonzero only where the
  guide genuinely misses"). Attachment is therefore evaluated on the
  crossing the AP designates — an in-region node inside the pin's
  candidate rect — which under that same model yields exactly **3**
  genuine escapes on gcd (see `graph-model.md` for the rule and the
  measured escape list).
- **`pin_shapes` is `fn`-private in `drt::access`** — the attachment
  check needs the pin's candidate `(LayerId, RectDbu)` rects, so it
  widens to `pub(crate)`. No other change to `access.rs`.
- `LayerId`/`PinId` are `Ord` (landed in `e6-drt-tracks`) — sorted
  collection needs nothing new in `interner.rs`.
- `picorv32.placed.def` is gitignored — generated by
  `tests/designs/picorv32/generate_ref.sh`; it was present on the
  planning machine. Tests panic loudly when absent (existing
  convention; same caveat as `e6-drt-tracks`).

## Decisions (detail in the sibling docs)

1. **Join wraps `resolve_guide_nets`** and adds the missing-net
   census: `missing_signal` (≥2-pin signal nets with no guide block —
   a named gap, gate-blocking) and `absent_expected` (single-pin nets
   and non-signal nets — OpenROAD emits no block for either, named but
   not a failure).
2. **Region = per-(net,layer) set of covered track-index pairs**
   `(ix,iy)` — the box-union clipped to the grid, enumerated per box
   as an index-range cross product. A node exists per covered pair;
   it is a real `(tracks_x, tracks_y)` crossing by construction.
3. **Edges = induced subgraph**: between nodes at consecutive track
   indices (`ix±1` or `iy±1`), both axes offered on every layer. The
   alternatives (consecutive-in-covered-set, which would wire across
   corridor gaps, and preferred-axis-only) are rejected — rationale
   in `graph-model.md`.
4. **Attachment = in-region node inside the pin's candidate rect**
   (the AP's designated crossing), not literal AP coordinates —
   measured 3 escapes on gcd vs ~834 under the literal rule.
5. **Findings stay named**: `missing_signal`, `zero_coverage`,
   `region_escape` — all printed per design; the gate checks the
   partition (every guided-net member pin attached ∨ named) and pins
   the measured escape set by name.

## Non-goals (per spec)

Maze search, cost assignment, rip-up/reroute, the via/layer-transition
model (needs LEF via geometry — next ticket), DEF route emission.
The graph does not decide which axis is legal on which layer — it
offers both.

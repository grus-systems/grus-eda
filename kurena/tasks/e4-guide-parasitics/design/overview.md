# e4-guide-parasitics — Overview

E4 ticket 2 of the sketch in
`kurena/tasks/next-stage-scoping/design/order.md`: build a `NetRcTree` per
net from route-guide boxes and compare per-net total capacitance against
OpenROAD's `estimate_parasitics -global_routing` in **both directions**
(done-when criterion 3):

- **(a) our model on their guides** — the pass gate. `parse_guides` on the
  committed `gcd.guide`/`picorv32.guide` → our guide-RC builder → per-net
  `total_wire_cap_pf` vs the `*D_NET` totals of `estimate_parasitics
  -global_routing -spef_file` produced on the same guide file: within
  `max(5%, 1 fF)` per net.
- **(b) their model on our guides** — measured, recorded, not gated. Our
  emitted guide → `read_guides` → `estimate_parasitics -global_routing`
  (the `check_guide_readback.sh` flow from e4-1) vs the same run on
  OpenROAD's own guide file. This cell measures guide quality downstream,
  not our RC code.

Anchors already measured (P-GR, `docs/results.md` 2026-11-22): guide-SPEF
total cap on gcd = 0.7397 pF (placement 0.4406, routed RCX 0.8962);
`_000_` `*D_NET` = 0.0009510 pF; `read_guides` read-back feeds
`estimate_parasitics` with identical per-net caps.

## Key decisions

- **Probe first, then model.** Before the builder is written, dump what
  `estimate_parasitics -global_routing -spef_file` emits on the committed
  `gcd.guide` and record the `*D_NET` structure (node naming, cap
  granularity, resistor count vs box count, via/stub handling) — see
  `probe.md`. The candidate model in `model.md` is written with explicit
  knobs; the probe answers pick the setting of each. If the SPEF alone is
  ambiguous, the pinned OpenROAD source may be *read* to explain the
  measured arithmetic (BSD — read, never copy; AGENTS.md §3).
- **Builder lives in `sta/parasitics.rs`.** `NetRcTree`'s fields are
  private to that module and both existing constructors
  (`estimate_placement_parasitics`, `spef_parasitics`) live there; a third
  `estimate_guide_parasitics` keeps all tree construction in one place and
  returns the same `NetParasitics` — no forked type, identical `pin_caps`
  handling downstream (`wire_cap_pf` stays wire-only, `PIN_CAP NONE`).
- **Guide input is name-resolved, not file-bound.** The builder takes
  per-net `GuideBox` lists keyed by `NetId`. A resolver in
  `congestion/guide.rs` maps `parse_guides` output `(String, Vec<GuideBox>)`
  to `NetId`s via the same `guide_net_name` matching the e4-1 tests use
  (raw DEF spellings); `NetGuide` from `build_guides` feeds the builder
  directly. Unknown net names are a hard error, never a skip.
- **CLI: `sta --parasitics guide`.** A `Guide` variant on the shared
  `ParasiticsMode`, plus `--guide <path>` on `StaArgs`. Without `--guide`
  the arm routes internally (`route_design` + `build_guides`) — that is
  the criterion-4 plumbing: one command runs our guides → our parasitics
  → our STA. `--spef-out` needs no changes; it already serializes whatever
  `NetParasitics` the arm computed through `write_spef`.
- **Golden shape: per-net caps tables as the assertion input.**
  `tests/designs/<d>/<d>.guide.caps.txt` — one `name cap_pf` line per
  `*D_NET`, extracted by a committed script from the guide SPEF — is what
  the tests compare against (exactly criterion 3's quantity, uniform
  across designs). `gcd.guide.spef` (~200 KB) commits too as the probe's
  evidence artifact and a ready `--spef` input; `picorv32.guide.spef`
  (~5 MB) is regenerated by the same script step and gitignored — the
  same split `*.routed.spef` already uses.
- **Both directions recorded; only (a) gates.** The (b) comparison runs
  `check_guide_readback.sh` (gcd, exists) and a new picorv32 sibling, then
  diffs the two OpenROAD SPEFs host-side with a committed helper
  (`tests/designs/guide_caps.py`). Fraction inside `max(5%, 1 fF)` and
  worst offenders go in `docs/results.md`.
- **The model rule lands in `docs/e4-guides.md` before/with the code**
  (AGENTS.md §7.6): a new "guide-based parasitics" section states the
  semantics the probe confirmed; the implementation commit references it.

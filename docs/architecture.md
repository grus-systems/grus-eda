# Architecture & Concrete Data Structures

This document is the architectural blueprint for `grus-eda`'s shared core: crate layout, ID types, numeric types, and Structure-of-Arrays (SoA) / Compressed-Sparse-Row (CSR) data structures. The per-stage algorithm documents (`e0-readers.md` through `e9-reporting.md`) are authoritative for stage-specific behavior.

---

## 1. Scope and Core Principles

`grus-eda` is a fast physical-design research toolkit for the SkyWater `sky130_fd_sc_hd` PDK. The performance target is to answer architectural exploration questions—routing congestion, placement density, static timing, power, and IR drop—in seconds on a laptop for designs up to ~100k cells; measured runtimes are recorded in `docs/results.md`. The pipeline also includes research implementations of global routing, clock-tree synthesis, detailed routing, and a LEF-expressible DRC subset. Sign-off, GDS output, LVS, full Magic-deck DRC, and production-quality detailed routing remain outside the prototype's claim; OpenROAD, OpenSTA, Magic, KLayout, and PDNSim are the reference tools.

1. **Agreement before speed**: A stage is complete only when its numbers agree with the relevant reference tool (OpenROAD, OpenSTA, Magic, or PDNSim) on the same inputs within the thresholds in `README.md` and `docs/status.md`, or when the residual is explicitly named. Parallelization (`rayon`), SIMD, `Accelerate`, and Metal come only after the baseline CPU implementation matches the reference tool.
2. **Decoupled stages**: Every stage reads and writes standard interchange files (`LEF`, `DEF`, `Liberty`, `SDC`, `SPEF`, `Yosys JSON` / gate-level `Verilog`, route guides, VCD/SAIF). Any stage can consume intermediate outputs generated by OpenROAD (such as an OpenROAD-placed `DEF`) or hand its output back to OpenROAD.
3. **Hybrid `i32` (DBU) + `f32` (arrays) + `f64` (scalar reductions)**:
   Our numeric types match the internal representations of the reference tools themselves—OpenDB (`int32` DBU), OpenSTA (`typedef float Delay`), and RePlAce / DREAMPlace (`float` arrays)—while avoiding `f32` reduction drift and exponential overflow:

   | Data Category | Rust Type | Rationale |
   |---|---|---|
   | Physical dimensions, pin offsets, row/site grids, legalized coordinates (LEF/DEF) | `i32` (DBU) | Matches OpenROAD's OpenDB (`1 DBU = 1 nm` in `sky130hd`). Eliminates floating-point rounding bugs (`0.9999999` vs. `1.0`) when checking cell abutment and site alignment. |
   | Total legalized HPWL sum across all nets | `i64` (DBU) | Prevents 32-bit integer overflow when summing DBU wirelengths across 100k+ nets. |
   | STA delays, slews, arrival/required times, pin/wire capacitances, NLDM tables | `f32` | Matches OpenSTA's internal `typedef float Delay;` (`~1 fs` precision over a `10 ns` clock period) and halves memory bandwidth. |
   | E2 placement coordinates, density grids, 2D DCT/FFT, and wirelength gradients | `f32` (`Vec<f32>`) | Matches RePlAce and DREAMPlace (`~1 nm` resolution across a `10 mm` die) and keeps the arrays suitable for CPU SIMD or a future Metal GPU path; the current implementation uses multi-core CPU parallelism rather than handwritten NEON or Metal kernels. |
   | E2 scalar reductions (total WA wirelength, $L_1$/$L_2$ norms, Barzilai-Borwein dot products) | `f64` (scalar accumulator) | Summing 100k+ `f32` elements in `f32` loses low-order mantissa bits and destabilizes Nesterov step sizes $\alpha_k$. Vectors stay `f32`, while `.map(\|&x\| x as f64).sum::<f64>()` (or tree/Kahan summation on GPU) preserves full accuracy at zero memory cost. |
   | E1 GCell routing demand & track supply | `f32` | Supports fractional demand in probabilistic/RISA routing while fitting in cache. |

## 2. Stage Ordering (Value-First Pipeline)

```
[Yosys JSON / Verilog] + [LEF / Liberty] + [DEF / SDC / SPEF / VCD / SAIF]
                                      |
                                      v
                                  +---------+
                                  |   E0    |  Readers, writers, caches
                                  +---------+
                                      |
implementation lane:        floorplan -> E2 -> E5 -> E4 -> E6 -> E7
analysis lane:              E1 congestion, E3 STA, N7 power, E8 IR drop, E9 reporting
interchange boundary:       standard files at every stage (DEF, SPEF, guides, JSON)
```

The lanes are logical, not a hard dependency order. Every stage can consume a
standard intermediate file produced by OpenROAD or by an earlier grus-eda stage.

- **E0 (Core readers and interchange writers)**: Ingests netlists, LEF/DEF geometry, and Liberty tables into flat in-memory structures, and provides the shared DEF, SPEF, and route-guide writers used by later stages. Readers for SDC, SPEF, VCD/SAIF, and guides are verified with the stage that consumes them. Stage CLIs own their JSON reports.
- **`floorplan` utility**: Generates a starting DEF from a public gate-level netlist. It is a convenience utility, not a reference-checked stage.
- **E1 (Congestion Estimate)**: Estimates global-routing overflow on a GCell grid. Accepting an OpenROAD-placed `DEF` directly turns E1 into a standalone preflight check.
- **E2 (Global Placement + Abacus Legalizer)**: Places unplaced netlists using analytical electrostatic placement (ePlace) and snaps cells onto valid rows with an Abacus legalizer followed by local refinement.
- **E3 (Static Timing Analysis)**: Computes arrival, slew, and slack in Kahn topological order using NLDM tables—zero-wire, placement-based RC, guide parasitics, or extracted `SPEF`.
- **N7 (Power Estimation)**: Estimates leakage, switching, and internal power from VCD/SAIF or propagated activity, using the same operating-point slew model as STA.
- **E4 (Global Routing and Guide Parasitics)**: Commits global-route paths, emits OpenROAD-format route guides, and derives guide-based RC parasitics for STA.
- **E5 (Clock-Tree Synthesis)**: Inserts a balanced clock buffer tree and emits a legalized CTS DEF for propagated-clock timing analysis.
- **E6 (Detailed Routing)**: Runs the guide-bounded maze router and emits routed DEF. Unrouted nets/pins and rule residuals are explicit outputs, not silent failures.
- **E7 (DRC Subset)**: Checks the LEF-expressible subset of the Magic deck over the assembled geometry model. It does not replace full-deck Magic DRC.
- **E8 (IR Drop)**: Extracts the PDN mesh, attaches instance currents, and solves the sparse DC system for voltage drop and ground bounce.
- **E9 (Reporting)**: Turns STA results into critical-path traces, per-clock-domain summaries, slack histograms, and machine-readable reports.

## 4. Core Data Structures (`grus-eda-core`)

### 4.1 Typed Indices & String Interner (`interner.rs`)

Strings are interned during E0 file loading and never touched inside hot loops:

```rust
use serde::{Deserialize, Serialize};
use std::collections::HashMap;

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, PartialOrd, Ord, Serialize, Deserialize)]
pub struct SymbolId(pub u32);

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct LibCellId(pub u16);

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct LibPinId(pub u16);

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct LayerId(pub u8);

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct MacroId(pub u16);

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct MacroPinId(pub u32);

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct CellId(pub u32);

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct NetId(pub u32);

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct PinId(pub u32);

#[derive(Copy, Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
pub enum PinDir {
    Input,
    Output,
    Inout,
    Internal,
}

#[derive(Default, Debug, Clone, Serialize, Deserialize)]
pub struct StringInterner {
    strings: Vec<String>,
    #[serde(skip)]
    map: HashMap<String, SymbolId>,
}

impl StringInterner {
    pub fn intern(&mut self, s: &str) -> SymbolId {
        if let Some(&id) = self.map.get(s) {
            return id;
        }
        let id = SymbolId(self.strings.len() as u32);
        let owned = s.to_owned();
        self.strings.push(owned.clone());
        self.map.insert(owned, id);
        id
    }

    pub fn resolve(&self, id: SymbolId) -> &str {
        &self.strings[id.0 as usize]
    }

    pub fn rebuild_map(&mut self) {
        self.map.clear();
        self.map.reserve(self.strings.len());
        for (i, s) in self.strings.iter().enumerate() {
            self.map.insert(s.clone(), SymbolId(i as u32));
        }
    }
}
```

### 4.2 Liberty Database (`lib_db.rs`)

All values in `LibDb` are normalized to **nanoseconds (`ns`)** for time and **picofarads (`pF`)** for capacitance during parsing so downstream STA code performs zero unit conversions.

```rust

use serde::{Deserialize, Serialize};

    PositiveUnate,
    NegativeUnate,
    NonUnate,

    Combinational,
    CombinationalRise,
    CombinationalFall,
    RisingEdge,      // CLK -> Q (rising clock)
    FallingEdge,     // CLK -> Q (falling clock)
    SetupRising,     // D vs rising CLK
    HoldRising,      // D vs rising CLK
    SetupFalling,
    HoldFalling,
    Preset,
    Clear,
    RemovalRising,
    RecoveryRising,
    Other,

pub enum TableAxisVar {
    InputNetTransition,
    TotalOutputNetCapacitance,
    ConstrainedPinTransition,
    RelatedPinTransition,
    Other,
}

#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct NldmTable {
```

## 5. CLI Subcommand Interface (`grus-eda`)

`crates/grus-eda/src/main.rs` exposes one binary with these subcommands.
`grus-eda <command> --help` is the authoritative flag reference.

| command | stage | purpose |
|---|---|---|
| `check-e0` | E0 | Verify Liberty, LEF, DEF, and netlist counts against OpenSTA/OpenROAD |
| `floorplan` | utility | Generate a floorplan DEF from Yosys JSON or gate-level Verilog |
| `congestion` | E1 | Estimate global-routing congestion from a placed DEF |
| `place` | E2 | Run global placement and Abacus legalization, emitting placed DEF |
| `sta` | E3/E9 | Run static timing analysis; optionally emit SPEF, JSON reports, and critical paths |
| `power` | N7 | Estimate leakage, switching, and internal power from VCD/SAIF or propagated activity |
| `route` | E4 | Emit an OpenROAD-format global-route guide |
| `cts` | E5 | Insert a clock tree and emit a legalized CTS DEF plus a JSON census |
| `drt` | E6 | Run the guide-bounded detailed router and emit routed DEF |
| `drc` | E7 | Run the LEF-expressible DRC subset checker on routed DEF |
| `irdrop` | E8 | Solve PDN voltage drop/ground bounce and write voltage maps plus summary JSON |

A representative implementation-flow invocation is:

```bash
grus-eda floorplan --tlef <tech.tlef> --lef <cells.lef> --json <netlist.json> --def-out <floorplan.def> ...
grus-eda place     --tlef <tech.tlef> --lef <cells.lef> --def <floorplan.def> --out-def <placed.def>
grus-eda cts       --tlef <tech.tlef> --lef <cells.lef> --lib <tt.lib> --def <placed.def> --sdc <design.sdc> --def-out <cts.def>
grus-eda route     --tlef <tech.tlef> --lef <cells.lef> --def <cts.def> --guide-out <design.guide>
grus-eda drt       --tlef <tech.tlef> --lef <cells.lef> --def <cts.def> --guide <design.guide> --out-def <routed.def>
grus-eda drc       --tlef <tech.tlef> --lef <cells.lef> --def <routed.def> --json <drc.json>
```

Analysis stages can enter at the same standard-file boundaries:

```bash
grus-eda congestion --tlef <tech.tlef> --lef <cells.lef> --def <placed.def>
grus-eda sta        --lib <tt.lib> --tlef <tech.tlef> --lef <cells.lef> --def <placed.def> --sdc <design.sdc> --parasitics placement
grus-eda power      --lib <tt.lib> --tlef <tech.tlef> --lef <cells.lef> --def <placed.def> --sdc <design.sdc> --vcd <activity.vcd>
```

The invocations above show the logical composition. The verified regressions are
per-stage and boundary-based; they are not a single full-flow golden run through
every command. Some research-stage commands still accept reference artifacts for
comparison printing or require design-specific calibration inputs. Those inputs
are part of the verification harness, not a claim that the stage is sign-off
automation.

# Review step 4: aes, ibex, jpeg through all stages; F2 map correlation

Step 4 of `docs/history/review-2026-11-11.md` Section 5. Today only gcd goes
through E0–E3 and picorv32 through E3. This step adds three public
designs from OpenROAD-flow-scripts (BSD 3-Clause; provenance recorded
in `tests/designs/README.md` per design, as for gcd), runs every stage
against the reference tools on each, closes F2 by replacing E1's
rank-order-only criterion with a congestion-map comparison, and gives
picorv32 its E2 row.

## Sources (surveyed 2026-11-14)

- `aes`: plain Verilog in ORFS `flow/designs/src/aes`
  (`aes_cipher_top.v` + sbox/key-expand/rcon files). Low risk.
- `jpeg`: plain Verilog in ORFS `flow/designs/src/jpeg` (DCT-based
  encoder, many small modules). Low risk.
- `ibex`: **not** in ORFS `src/` any more. The RTL is lowRISC/ibex
  (Apache-2.0), SystemVerilog, with a FuseSoC core file list and
  `prim_*` technology modules that need the sky130 synthesis stubs
  ORFS uses. This is the known hard case and is sequenced last, with
  a checkpoint (below).

Per design: copy the RTL + LICENSE into `tests/designs/<design>/`,
write `<design>.sdc` and `config.yaml` following the ORFS sky130hd
parameters (clock period, die/core sizing for high utilisation — E1
needs real congestion), and record origin URL + commit + license in
`tests/designs/README.md`.

## Reference generation

Adapt `tests/designs/gcd/generate_ref.sh` per design (same LibreLane
container, same step shape): synthesis (Yosys JSON + Verilog),
floorplan + placed DEF, routed SPEF, `<design>.reference.json`,
`<design>.sta.reference.json`, and two E1 artifacts:

- the existing step-7b GCell grid/resource dump, and
- a **per-GCell usage dump after `global_route`**: for every GCell,
  OpenROAD's usage per layer aggregated to the same (x, y) cell our
  congestion code reports, written by the script's Tcl (never by
  hand). The exact Tcl API is a spike item (see order below); the
  dump format is one line per GCell: `x y usage capacity`.

Golden files are committed when each is < 1 MB (AGENTS.md rule);
larger ones are git-ignored, generated by the script, and the CI
workflow gains a generation step for them (picorv32 precedent).

## Stage wiring

- **E0**: count comparisons against `<design>.reference.json` — the
  harness pattern from gcd, generalised per design.
- **E1 (F2)**: new map comparison per design at the high-utilisation
  placed DEF: Spearman rank correlation between OpenROAD's per-GCell
  usage and ours, plus the overlap of the top 5% most congested
  GCells. Thresholds are set from the first measured values with a
  stated margin and recorded in `docs/results.md`; the README E1
  "done when" is then rewritten to the map criterion (the gcd
  rank-order test stays as a smoke test). Spearman/overlap helpers
  live in the congestion test code (no new dependencies).
- **E2**: per design, run GP + legalization in a test at the
  reference floorplan; assert legality (`verify_legality`) and HPWL
  within 5% of OpenROAD's placed HPWL (README criterion), recording
  the actual gap. Designs whose GP does not converge report it
  honestly (F1 behaviour) and record the outcome instead of passing
  silently.
- **E3**: the existing `compare_design_with_opensta` harness per
  design (zero-wire, placement RC, SPEF where the script produced
  one), tolerances per design following the gcd/picorv32 pattern;
  any design that misses a tolerance gets a `docs/results.md` entry
  with the root cause, not a widened tolerance by default.
- **picorv32 E2**: a test that runs placement end to end on the
  generated floorplan and records convergence status, legality and
  HPWL; `docs/status.md` gains the honest E2 picorv32 row (today:
  GP non-convergence within the iteration limit).

## Order

## Review resolutions (external review, 2026-11-14)

The full review text is not included in this repository. Verdict: adopt
with changes. Adopted, with one structural adaptation:

- **Metric (Q1, S2), adapted**: the reviewer asked for per-layer
  Spearman on overflow. Our estimator does not retain per-layer maps:
  it aggregates layers into per-direction GCell **edge** demand and
  capacity (the structure documented in `docs/e1-congestion.md`), and
  OpenROAD's router is likewise edge-based per layer. The comparison
  therefore runs per direction (H edges, V edges): OpenROAD's per-layer
  edge usage/capacity is summed over layers in the dump, and the
  correlated quantity is per-edge overflow `(demand - capacity)+`
  over the support set of edges with demand > 0 in either map. The
  reviewer's core points stand and are kept: no whole-grid raw-usage
  Spearman (zero-tie mass), overflow not raw usage, support restricted
  to nonzero-demand edges, grid alignment asserted from the dump's
  recorded origin/pitch before correlating. Top-set overlap uses the
  overlap coefficient on the top 5% of support edges by overflow, or
  all positive-overflow edges when those are fewer.
- **Thresholds (Q2, S1)**: not fitted to measurements. The criterion is
  fixed here: per direction, Spearman rho must be **>= 0.60** and
  **>= the 95th percentile of the negative-control distribution +
  0.15** (controls: the OpenROAD map shifted by one GCell, and a
  permutation of its values over the support, both computed in the
  same test run and recorded), and the top-set overlap must be
  **>= 0.50**. If a design fails, the outcome is recorded with a root
  cause; the thresholds do not move.
- **Golden determinism (Q3, S2)**: the container image is pinned
  (`librelane:3.0.16`); per design, the SHA-256 of every generated
  golden file is recorded in `tests/designs/README.md` at generation
  time, and the maintainer checks the CI generation log against them
  on the first CI run.
- **ibex checkpoint (Q3, S2)**: timebox one working day of spike
  effort. Success = Yosys synthesis completes in the container with
  the sky130 prim stubs and produces a netlist. Fallbacks to present
  to the user if it fails: pin an older ORFS commit that still ships
  ibex sources; an sv2v conversion route; or closing step 4 with
  aes/jpeg + picorv32 only.
- **GP density fallback (Q3, S2)**: E2 starts at the ORFS density; on
  non-convergence the target density steps down in documented steps
  and the density actually used is recorded. E1 always uses the
  OpenROAD high-utilisation placed DEF, independent of our GP.
- **STA tolerances (Q3, S2)**: a per-design tolerance is allowed only
  with a named root cause and a sunset condition in `docs/results.md`.

## Measurement note (2026-11-14, aes first run)

The aes reference generation ran end to end on the first attempt.
Measured property of the reference tool that changes the E1 metric:
on `aes.util65.def`, OpenROAD's global router saturates at a usage
ratio of exactly 1.0 — **zero edges overflow** (median edge usage
ratio 0.78–0.82, p99 1.0, both directions; grid 55x55 at 6900 dbu).
Per-edge overflow on the reference side is therefore an all-zero
map and cannot be correlated. The correlated quantity is the
per-edge **usage ratio** (demand / capacity), per direction, over
all edges with capacity > 0 in the dump; the top set is the 5%
hottest edges by ratio. The thresholds and negative controls from
the review resolutions are unchanged. This is a deviation from the
reviewer's overflow-first recommendation, forced by the measured
behaviour of the reference router; our own estimator's overflow
figures remain reported as before.
